# User-facing copy

This page is for the text that the users of a product read: product READMEs, landing pages,
release notes for users, announcements, emails, CLI messages and app store text. UI text follows
[content and localization](../ui/content-and-localization.md) too.

The [writing rules](index.md) still apply to this text. A project's voice guide can set the tone
and the product terms. Where the voice guide and this page differ, the voice guide wins. It does
not replace the writing rules.

## Rules

- Put the one thing that the reader must do or know first.
- Say what the product does in concrete words. Name the task that it helps with.
- Do not invent numbers, quotes, customers or comparisons. Use only facts that you can show. See
  [AGENTS.md](../AGENTS.md#key-rules).
- No hype words and no cliches. Do not call a product "revolutionary" or "seamless".
- Do not use fake urgency or fake scarcity, for example a countdown that resets or "only 3
  left" when it is not true. The [deceptive pattern rules](../ui/principles.md#no-deceptive-patterns)
  apply to email and pages too.
- In release notes and announcements, name breaking changes and the user action first. Then the
  other changes.
- A call to action starts with a verb and says what happens next, for example "Download the
  report".
- Use each product name and term the same way in each text.
- A CLI message says what happened and what the user can do next.

## Good example

```
Version 2.0 removes the old export format. Before you update, export your data again.
```

The breaking change and the action come first.

## Bad example

```
We're thrilled to announce our most powerful release ever! Act now, offer ends soon!
```

Hype, fake urgency and no facts.
