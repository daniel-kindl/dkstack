# UI principles

- Design for the user's tasks, context, and available input methods. Check the task's intended audience before choosing a presentation.
- Prefer clear and predictable behavior over decoration. Each interactive element needs a meaningful purpose.
- Use the smallest change that meets the task; do not redesign neighboring surfaces without authorization.
- Apply platform conventions where they improve familiarity and accessibility. Do not imitate another platform at the cost of expected behavior.
- Preserve functionality when visual enhancement is unavailable, including poor network conditions and limited display space.
- Include relevant loading, empty, failure, and success outcomes in acceptance criteria.
- Treat usability and accessibility as requirements, not postimplementation decoration.
