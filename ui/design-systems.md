# Design systems and visual direction

The project owns its branding, tokens, components, and platform conventions. DKSTACK defines the quality requirements.

## Conditional autonomy

1. Inspect existing screens, tokens, styles, components, and project requirements.
2. If a coherent visual system exists, follow it. Do not introduce a competing palette or component style.
3. If the system is partial, extend it consistently. Record material additions where the project keeps design decisions.
4. If no visual direction exists, choose one based on product, audience, platform, and task. State the rationale and keep the decisions small and reversible.
5. Ask the owner only when competing choices materially affect branding or product identity and cannot be resolved from available requirements.
6. An explicit redesign request can authorize exploration, but not unrelated scope expansion.

Avoid imposing any one product's look or generic AI styling. Preserve accessibility and usability regardless of aesthetic choices.

A project may document exceptions to DKSTACK rules under the process in [AGENTS.md](../AGENTS.md); safety rules cannot be excepted.
