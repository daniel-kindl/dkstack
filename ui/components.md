# Components

- Reuse project components and documented design tokens before creating new ones.
- Give controls accessible names and clear affordances. Do not make noninteractive decoration appear actionable.
- Specify applicable states: default, hover, focus, pressed, selected, disabled, loading, empty, error, and success. Do not invent states irrelevant to the component.
- Use consistent behavior for the same action across the product.
- Keep behavior and visual presentation separable where the architecture allows it. Add abstraction only when it helps maintainability.
- Test component behavior through [TDD](../tdd/index.md) and the project's UI testing approach.
