# Prototype to learn

Build a small prototype when you need to learn.

A prototype answers a question. It is not production code.

## Rules

- Prototype only the uncertain part.
- Throw the prototype away or clearly mark it as non-production.
- Do not polish a prototype into the final system.
- Use the knowledge from the prototype to build the real solution.

## Good example

You are unsure whether a data flow will work. You build a minimal version that only tests the flow. You learn the answer and discard the code.

## Bad example

You build a prototype, then keep adding features to it until it becomes the production system. The early shortcuts remain.
