# KISS

Keep it simple.

Prefer the simplest solution that works.

## Rules

- Choose the option with fewer parts.
- Do not add flexibility you do not need yet.
- Remove complexity that does not serve the current requirement.
- Simple does not mean incomplete. It means no unnecessary parts.

## Good example

A direct path from input to output with one clear step.

## Bad example

Multiple layers, configuration options, and extension points for a requirement that has only one case.
